# PROBE: the spider-boss big-UFO sparing counters exist, and the engage-radius gate ENGAGES.
#
# PINS: card 2c74d5b7. Read this file and ai_bigufo_gate_off.txt as ONE probe in two files (the
# ai_wallnav_2008 / ai_swept_guard idiom) -- a probe's flags are per-file, and this pair is an
# A/B. This is the POSITIVE half and it sorts first on purpose: a build where the gate never
# engages must fail HERE, rather than pass by both halves quietly agreeing on a do-nothing.
#
# WHAT IS BEING PINNED, and why it needed building at all. Only a Lazer hurts the SpiderBoss
# (SpiderBoss.CollidesWith) and a BIG UFO fires one six times as often as a small one
# (UFO.Update: 0.0009/ms against 0.00015), so the big-UFO population the bot leaves alive IS the
# fight's clock. Nothing else in AiBench could see it -- "the AI kills too many of them" was an
# impression with no number behind it. Three fields now carry it, all no-op without ?aibench:
#   bigufo=    mean big UFOs alive per tick while a spider boss lives  -- the OUTCOME
#   bigspared= mean deliberately spared per tick over the same ticks   -- the DECISION
#   bigalive=  the count at the instant the boss died, -1 if it never  -- the card's literal ask
#
# `bigspared` IS WHAT THIS PROBE ASSERTS ON, and the choice is the whole reason the probe works.
# `bigufo` is an outcome that the spawner's rolls and the bot's aim both move: measured across
# seeds it swings 1.24..1.95 on ONE arm, which straddles the gate's entire effect. `bigspared`
# is the rule's own output, so it separates cleanly -- 0.45 shipped against 0.67..0.86 with the
# gate on, on this seed, with the shipped side reading 0.45 on every repetition.
#
# WHY THE RIG IS PINNED THIS HARD:
#   ?spiderboss      the only fast-boot with a live SpiderBoss and its linked big-UFO spawner.
#   ?spiderbosshp=99 THE PRECONDITION, ASSERTED RATHER THAN WAITED OUT (card af4c3694). At stock
#                    HP (~5) the boss dies partway through the soak; after that no tick is
#                    sampled, the fields are SUPPRESSED, and the probe would pass or fail on
#                    whether this seed happened to win. The fat pool keeps the fight up
#                    throughout. Consequence: bigalive is legitimately -1 here, so only its
#                    PRESENCE is asserted -- ai_bigufo_death.txt covers the value.
#   ?seed=5          the thresholds below are real measured bands, not round numbers. Unseeded,
#                    "did the gate engage" becomes a coin flip.
#   ?invuln          a death costs the bot ticks, and both fields are per-tick means, not
#                    survival. This probe is not measuring whether the bot lives.
#
# NOTE THE GATE IS OFF IN THE SHIPPED BUILD -- `?aibigufopx=250` below is what turns it on.
# DefaultBigUfoEngagePx bakes to 0 because every value in its usable band measured as a net loss
# on this rig (the table is at the constant). That is why the seam has to be probed at all: an
# always-off feature rots silently, and the next person to re-open the question would sweep a
# dead flag and conclude the mechanism does nothing.
#
# FAILURE MEANS:
#   * `bigufo=`/`bigspared=`/`bigalive=` missing -> the AiBench.NoteBigUfos hook or the
#     Line()/Row() fields are gone. Both output paths carry them; Row() unconditionally, Line()
#     only when a boss lived.
#   * bigspared in the OFF band                  -> ?aibigufopx= no longer spares a second UFO.
#     Look at PlayerShip.SelectSparedBigUfos: the second slot (sparedFarUfo) and the
#     `engagePx <= 0f || sparedFarRoom <= engagePx` guard beside it.
#   * bigufo trivially 0                         -> the fight never started; the rest proves
#     nothing. Check the boot, not the gate.
#
# MUTATION-TESTED: dropping the `sparedFarUfo` assignment turns the bigspared leg red here while
# ai_bigufo_gate_off.txt stays green (which is exactly how invisible this would otherwise be);
# deleting the NoteBigUfos call turns the presence legs red in both files.
#
# eahl: --flags "?level=Level2&spiderboss&aiplayer&aibench&invuln&difficulty=Very_Hard&spiderbosshp=99&seed=5&noattract&aibigufopx=250"

step 150 nodraw
mark

# 120 sim-seconds of real fight.
eval AiBenchReset
eval AiBenchRun 60
eval AiBenchRun 60

# The value legs below must see the FINAL report and nothing else. AiBench prints a summary every
# 10 sim-seconds, so a window covering the whole soak would let `expect` match a passing early
# transient -- the run opens with almost no big UFOs on screen, so a low `bigspared` line exists on
# every arm, and a high one appears on any arm that gets a busy moment. Measured on the sibling
# file, where the consequence is starkest: without this second mark, re-baking
# DefaultBigUfoEngagePx to 250 leaves ai_bigufo_gate_off.txt GREEN. Do not widen the window.
mark
eval AiBench

# 1. all three fields are emitted.
expect bigufo=[0-9]+\.[0-9]+ bigspared=[0-9]+\.[0-9]+ bigalive=-?[0-9]+

# 2. the fight really happened -- big UFOs were alive. Without this the leg below could be
#    satisfied by a run that spared nothing because there was nothing to spare.
expect bigufo=[1-9][0-9]*\.[0-9]+

# 3. THE LEG (gate on).
expect bigspared=0\.[6-9][0-9]
