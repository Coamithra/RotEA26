# PROBE: the top-edge danger band is COMPOSED with the other repellents (the shipped placement)
#
# PINS:   card 13960838. The band is 5x `maxSteerStrength`, and `maxSteerStrength` is also the
#         ceiling of the powerup approach pull -- so where the band lands in DoAIMove decides
#         whether a pickup near the top of the screen is reachable at all. It used to be added to
#         `direction` AFTER the steering low-pass, i.e. neither damped nor eligible for the
#         repulsion-cancel floor; it now sums into `repel` with every other repellent.
#
#         That is a PLACEMENT, and placements fail silently. Both arms compile, both boot, both
#         fly, and `[debug] flags active` reports only the PARSE -- so a build whose branch went
#         the wrong way prints an entirely plausible bench table with a small difference in it,
#         which is precisely how a sweep arm comes to measure the shipped code twice (the
#         `?aiwallnav2008` lesson). `[aitopedge] placement:` is emitted from the point of use and
#         names the branch that actually ran, which is the only observable that separates them.
#
#         Read this probe together with its control, ai_top_edge_precard.txt -- one proves the
#         shipped build composes, the other proves the flag can still reach the pre-card
#         placement. Either alone passes on a build where the branch always takes one side.
#
# FAILURE MEANS: read WHICH line went red.
#         [aitopedge] missing entirely -> DoAIMove never ran, so the run proved nothing either
#                                way (precondition, README rule 5). The fast-boot or the AI seat
#                                moved; check the flags line and that a ship exists.
#         "placement: post-smoothing" -> THE REGRESSION: an ordinary boot is flying the pre-card
#                                placement, so the band is once again vetoing every attractor in
#                                its own 170px.
#         band=/strength= changed -> card 2248e5eb's measured magnitudes were retuned. Not
#                                necessarily wrong, but its N=60 verdict was taken at 170/20 and
#                                does not transfer; re-measure before believing a bench number.
#         aitopedgecompose=0 on the flags line -> the seam is being set by something other than
#                                the URL, which is how a deliberate bug repro reaches a player.
#
# NOTES:  The spider rig on purpose: its lane escapes (18) are the term's own stated competitor,
#         and it is the rig where the pickup rate moved most in the card's directional sweep.
#         ?invuln pins the precondition -- without it the bot can die before it has flown
#         anywhere and a short run ends with nothing to assert.
#         MUTATION-TESTED TWICE, and the first attempt at this probe FAILED both -- worth knowing
#         before trusting a similar one:
#         (a) inverting the dispatch (`if (!TopEdgeComposes)` on the `repel` site) turns this
#             probe AND its control red while the flags line stays green. It did NOT while
#             `[aitopedge]` was derived from `TopEdgeComposes` at a single site instead of being
#             passed each branch's own name -- the report was then just a second reading of the

#             at BOTH sites, so double strength on an ordinary boot -- turns the `expect-not`
#             below red. It did NOT while the two sites shared ONE report latch, because whichever

# The flags dump was printed at all, and does NOT carry the seam. Asserted BEFORE the first
# `mark`: the dump is a BOOT line, so marking above it discards the subject. The positive half is
# what stops the expect-not being vacuous on a run that printed no dump whatsoever.
# `level=Level2`, not `spiderboss` -- the level FAST-BOOTS are not named in the dump at all
# (verified: the spider rig's line ends `aiplayer aibench`), so an expect on the fast-boot's own
