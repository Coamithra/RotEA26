# PROBE: the bomb ripple ring FOLLOWS its blast, in location and duration (card 03c379f2).
#
# PINS: the WIRING half of the follow behaviour -- Blast.Initialize seeding the ring with the
# blast's real lifetime via BombRipple.Fire's duration arg, and Blast.Update pushing the live
# position through BombRipple.MoveRing(token, pos). The decision layer (token matching, per-ring
# duration resolution, the stale-token/eviction no-ops) is logic_probe's ProbeBombRippleFollow;
# this probe is what fails when either hook in Blast.cs is deleted, which logic_probe cannot see.
#
# FAILURE MEANS one of three silent breakages:
#   * no `/3.00` on the first RippleState -- Blast.Initialize stopped passing its lifetime, so
#     every ring is back on the fixed 0.75 s fallback and dies ~2-4 s before its blast.
#   * the ring still reads `(200,300` after the move -- Blast.Update stopped calling MoveRing
#     (or the token went stale), so the ring is left behind the explosion it decorates: the
#     card's original complaint. Nothing else says a word; a ring at the wrong place moves no
#     counter and draws a perfectly plausible frame.
#   * `visible=True` at the last check -- the ring is no longer expiring with its blast.
#
# RippleBlast/RippleBlastMove spawn and drag a REAL Blast through the real ComponentBin -- the
# same Setup -> Add -> Initialize path a bomb takes and the same SetPosition drag
# PlayerShip.Update applies -- because eaRipple.fire (the old rig) never touches Blast at all:
# a probe on it passes with both Blast hooks deleted, the regression most worth catching.
#
# Menu boot: the blast is a genuine component (draws, collides, dies at its own lifetime), so
# it runs where there is nothing to hit. ?noattract so the idle demo cannot steal the world.
#
# eahl: --flags "?menu&noattract"

# The blast lives 1000ms * (power+1) = 3 s at power 2; the ring must report that as its own
# resolved duration, and its centre must be the spawn point.
step 10
eval RippleBlast 200 300 2
step 5
eval RippleState
expect \[ripple\] blast spawned at 200,300 power=2
expect \[ripple\] visible=True
expect r[0-3]=\(200,300 e=0\.0[0-9]/3\.00

# Drag the blast the way PlayerShip.Update drags it; the ring must be re-centred on the
# blast's next tick. Fresh window so the spawn-point line above cannot satisfy anything here.
mark
eval RippleBlastMove 500 400
step 3
eval RippleState
expect \[ripple\] blast moved to 500,400
expect r[0-3]=\(500,400
expect-not r[0-3]=\(200,300

# Past the blast's OWN 3 s life (180 frames at the fixed 60 Hz dt; we are ~18 frames in, so
# 200 more is comfortably past it): blast and ring must be gone together.
mark
step 200
eval RippleState
expect \[ripple\] visible=False
expect-not visible=True
quit
