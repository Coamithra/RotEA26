# PROBE: the online game browser draws SOMETHING for a level it has no bundled art for.
#
# PINS: SubMenuOnlineGames.EnsureArt's null-ScreenshotPath branch (card 0d166364), and the two
# deliberately unmapped fake entries in NetGameBrowser.InjectFakeGames that are the only way to
# reach it offline.
#
# NOTE THE FLAG VALUE: `?gamebrowser=fallback`, not bare `?gamebrowser`. The bare flag is the
# APPEARANCE rig (card 2001fbd8) and lists four real-looking games; the two unmapped entries are
# wrong for it, since both draw Mission 1's art under the generic "Mission" title and a reader
# of that screenshot would have to know to discount them. Booting this probe with the bare flag
# prints NO line at all (four entries, every one of them mapped) and so fails the expect below.
# That is the intended behaviour, not a bug to work around by loosening the assertion.
#
# WHY IT EXISTS: card 0d166364 collapsed LevelArt's two parallel switches into one nullable
# ScreenshotPath, which meant deleting a `_ => "GFX/Screenshots/level1empty"` default that was
# DELIBERATE. A listed game's Level arrives off the wire as an int from a stranger's build, so
# it can name a level we know but have no carousel art for (Tutorial), or one our Levels enum
# does not contain at all (a NEWER peer's build). Either way a listed game must always have
# something to draw. Moving that fallback to the call site made it the browser's job, and this
# is what checks the browser actually does it.
#
# FAILURE MEANS: no `[gamebrowser] rebuilt` line, or one naming the wrong levels. The line is
# printed ONLY when something resolved to no bundled art -- a public lobby rebuilds every time a
# game opens or closes and the answer is always "all mapped", so logging that would be noise on
# the player's path. Its absence therefore means either EnsureArt stopped recognising an unmapped
# level (its guard is gone, or it is loading art for one) or the carousel never built at all.
#
# THE SILENCE THIS WORKS AROUND, and it is the whole reason the readout exists: EnsureArt wraps
# its Content.Load in `catch (System.Exception)` and falls back to level1empty. So a BROKEN
# fallback -- handing Content.Load a null path -- throws, gets absorbed, and draws exactly the
# same picture as the working one. There is no exception to expect-not and no screenshot that
# could tell the two apart. The `[gamebrowser] rebuilt` line is therefore reported from what
# EnsureArt RECORDED while resolving (SubMenuOnlineGames.unmappedArtLevels), never re-derived
# from LevelArt at the report site: a second copy of the test would keep printing the right
# answer with the guard deleted, and this probe would pass on the mutation it exists to catch.
#
# THE POSITIVE CONTROL is `entries=6`, and it is why the assertion below is an `expect` on an
# exact string rather than a loose match. `?gamebrowser` hijacks the boot (SkipSplash +
# AutoStart), so there is no navigation here that could prove itself the way the menu-driven
# probes do; the count is the proof, since it can only come from a rebuild that walked all six
# injected entries. Bump it if InjectFakeGames grows.
#
# NO `mark`: the subject line is printed during boot, on the first rebuild, so a mark would drop
# the very thing being asserted. The window is the whole run, which is short (no navigation, no
# level load) and well inside the capture cap.
#
# eahl: --flags "?gamebrowser=fallback&noattract"

step 240 nodraw

# Both unmapped fakes, in injection order. Tutorial is in our enum with no carousel slot; 9999
# is not in the enum at all and formats as the bare int -- that is the newer-peer case.
expect \[gamebrowser\] rebuilt entries=6 unmappedArt=Tutorial,9999

# The four MAPPED fakes (Level1/Level2/Level3/ClassicAliens) must NOT be listed: a fallback that
# fired for everything would satisfy the expect above while silently replacing every game's art
# with Mission 1's.
expect-not \[gamebrowser\] .*unmappedArt=.*(Level1|Level2|Level3|ClassicAliens)

# Card 88f87ba2. The FU7UR row also carries an out-of-range DIFFICULTY (7, against an enum that
# stops at Inzane=4) -- the other half of what arrives off the wire, and the only offline rig for
# the difficulty sentinel. Two things are being pinned at once here:
#   (a) the boundary REFUSES it, i.e. GameEntry.KnownDifficulty is null and the carousel draws
#       LevelArt.DifficultyName's "?" rather than casting 7 to a DifficultyLevel;
#   (b) the row is still LISTED -- entries=6 above covers the whole set, so a sentinel that
#       dropped or threw on the row would take that count to 5 and fail there instead.
# Only ONE unknown difficulty exists in the fake set, so a fallback firing for everything would
# print the other rows' tiers here too and fail the expect-not below.
expect \[gamebrowser\] .*unknownDifficulty=7
expect-not \[gamebrowser\] .*unknownDifficulty=.*(0|1|2|3),
quit
