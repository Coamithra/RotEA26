# PROBE: an EvReset purging from inside the rx drain must not let SpawnPuppet/SpawnFriend adopt a
# ship the ComponentBin diverted.
#
# PINS: card 74403f83's two ship-puppet spawn sites (NetSession.SpawnPuppet,
# NetSession.Friends.SpawnFriend) END TO END, which is what card 25ad0659 step 1b added. The fix
# itself shipped in PR #160 but was only ever proven at the PRIMITIVE -- eaBinTest scenario 5 is a
# bare ComponentBin.TryAdd landed/diverted pair. Reaching the real call sites needs a live session
# with a host-granted peer slot and buffered ship samples, so until this probe there was nothing
# that could tell the fix from its absence at the sites that have it.
#
# WHAT IT ASSERTS, in the suite's own three legs (Compat/Net/NetResetSpawnTest.cs has the full
# reasoning): NEGATIVE -- the LoseLife / UpdateWin / UpdateResetting purges are flushed before the
# drain, so both callers' gates are shut and NEITHER SEAT is even allocated; POSITIVE -- an EvReset
# purges from inside the drain, where the local ship's death is still merely QUEUED, so both
# callers DO take their seat and both TryAdds are refused with nothing adopted; POSITIVE -- one
# TopOfTickFlush later the identical sequence adopts both puppets in those same seats. Leg 3b
# (card 25ad0659 step 2a) then advances ONLY the injected virtual clock -- stepped, with a primary
# heartbeat before each step, since card 14c5943e made the friend timeout require the link to be
# otherwise ALIVE (total silence is a protected hiccup) -- and requires the session to act on it,
# which is what proves NetSession.Update's cadence really reads the seam.
#
# LEG 0b (card 25ad0659 step 2b) rides along here for a reason worth stating: the four
# ServiceHelper.Get<>() lookups the net cores made now go through INetHost, and a call site left
# on the process-global registry is INVISIBLE today -- it changes no behaviour at all until step 3
# puts two peers in one process and they quietly share an Oracle. This suite is the only thing in
# the repo that starts a real session headlessly, so it is the only place that read can be
# counted. It requires the EXACT count each core makes (oracle 1, bin 2, sound 1, score 2 -- bin
# and score twice because a CLIENT session also runs NetPuppets.Enable); a floor would let
# NetPuppets.Enable regress behind StartWith's own read of the same service.
#
# LEG 3c (card 25ad0659 step 2c) rides along for the same reason 0b does, one seam later. World
# messages now reach the scene through NetScene.Current instead of GameScene.NetActiveScene, and a
# handler left on the old field does the IDENTICAL work today -- the seam reads through that very
# field -- so nothing observable diverges until step 4 supplies a scene of its own. A
# RecordingNetScene decorator over the LIVE scene (not a fake: leg 2's real Purge<PlayerShip> is
# the whole subject here) counts the arrival instead. Mutation-tested: reverting the EvReset
# handler to GameScene.NetActiveScene fails exactly one assertion, `resets=0`.
#
# THE SPAWN COUNT IN 3c IS THE RECEIPT FOR A DELETED FAKE. Step 1b had to hand-roll a stand-in for
# GameScene.SpawnAllPlayers' respawn of the local seat, and its own comment listed four ways it was
# not a faithful copy (no Recycle, no spawnType position, startup:false, none of the caller's
# cursor bookkeeping). SpawnPlayer is on INetScene, so both retry legs now drive the REAL one; the
# fake and all four caveats are gone. That was the last outstanding debt step 1b filed.
#
# FAILURE MEANS: read the quoted PASS/FAIL line, they name what they check. A leg-2 failure
# ("TryAdd was refused, so no ... puppet was adopted") is the card's own defect back: a puppet
# adopted but absent from the world. A leg-1 failure means a spawn gate stopped requiring a local
# ship, which makes the NEGATIVE claim in that file wrong and the whole scenario reachable from
# purge sites it says it is not. A leg-3 failure means the retry no longer fires.
#
# THE POSITIVE IS THE `42 passed` TALLY. Leg 3 is ALSO leg 1's and leg 2's positive control -- it
# runs the identical send/pump/Update sequence and DOES adopt, so their "nothing happened"
# assertions cannot be passing because the scripted peer's frames never arrived. Each leg
# additionally asserts the endpoint's RxDelivered advanced by exactly the frames it sent, and leg 0
# asserts the roster PRECONDITION, so a boot with a different roster reports rather than asserting
# about the wrong thing. `expect-not FAIL` is here as well but is the weaker half: it passes on a
# run where the eval never happened (a renamed DebugInput method), which the tally catches.
#
# MUTATION-TESTED SIX WAYS, each isolated, each a REVERT of something the suite claims (counts are
# failing LEGS):
#   * SpawnPuppet back to the pre-card `bin.Add` + unconditional adopt -> **1** (leg 2's remote
#     assertion, and ONLY that one -- see the note below).
#   * SpawnFriend the same way -> **1** (leg 2's friend assertion).
#   * drop `Collection.Purge<PlayerShip>()` from GameScene.NetApplyReset -> **6**. This is the one
#     that proves leg 2 is not passing for some other reason: with no filter armed, both TryAdds
#     land and both puppets are adopted early.
#   * drop `FindLocalShip() != null` from ManagePuppet's spawn gate -> **1** (leg 1's
#     "SpawnPuppet was never entered").
#   * drop it from TickFriends' spawn gate -> **1** (leg 1's SpawnFriend twin).
#   * drop `pendingPurges.Clear()` from ComponentBin.TopOfTickFlush -> **12** (the filter never
#     expires, so nothing is ever adopted).
#   * NetSession.NowMs back to Environment.TickCount64 -> **1** (leg 3b's friend-timeout
#     assertion, and only it -- the wall clock cannot hear the virtual one advance). Added by
#     card 25ad0659 step 2a; it is the only leg here that discriminates on the clock at all.
#
# AND SIX MORE FOR LEG 0b (card 25ad0659 step 2b), each isolated, each a revert of ONE call site
# back to `ServiceHelper.Get<>()`. Every one fails exactly ONE assertion and names its service:
#   * NetSession.StartWith oracle -> oracle reads=0 · bin -> bin reads=1 · sound -> sound reads=0
#     · score -> score reads=1
#   * NetPuppets.Enable bin -> bin reads=1 · score -> score reads=1
# THE SEVENTH 2b CALL SITE IS NOT REACHABLE FROM HERE AND HAS NO RUNTIME COVER, which is worth
# stating plainly rather than implying. NetPuppets.WireRoundTripTest resolves its own score
# lookup, and it runs under eaNetScore.test with no host installed -- so it resolves to the same
# live ScoreVisualiser before and after the change and net_selftests.txt's `[netscore] wire PASS
# (9/9)` leg passes identically either way. That leg is a NO-REGRESSION check, not coverage;
# verify_decompiled_diff.py is the actual evidence that the line moved.
# (It is also the one piece of TEST code deliberately put ON the seam, against INetHost's own
# policy that the sibling suites stay on the registry: unlike them it does not assert about the
# live world, it borrows a ScoreVisualiser to round-trip a wire frame through -- so a step-4
# scenario should get its own, not the process's.)
#
# READ THAT FIRST MUTATION CAREFULLY -- it is only ONE leg, and the reason corrects a claim card
# 74403f83 left in two CLAUDE.md files and in SpawnPuppet's own comment. Those say adopting a
# diverted ship strands the remote player "for the rest of the session"; it does not.
# `ManagePuppet` (and `TickFriends`) open by RELEASING a puppet the oracle does not hold
# (`!oracle.GetShips().Contains(puppet)`), and that block has been there since Stage 11.1
# (`6f36aae`), long before the fix -- so the pre-card bug self-heals on the NEXT tick and its real
# window is one tick, not the session. The fix is still right (adopting something that is not in
# the world is wrong, and the release is a safety net rather than the intended path), but the
# severity claim is overstated. Leg 2's single assertion is therefore the load-bearing one here;
# do not add legs expecting the broken code to stay broken into leg 3.
#
# LEGS 0a / 5 / 6 ARE THE DEATH-AND-RESET ARTIFACT PAIR (cards 68f62e92 + b4d0ba1d). They live
# here rather than in a probe of their own because both need the same three expensive things this
# suite already stands up: a live GameScene, a real session over the in-process wire, and a
# scripted peer whose ship stream can be driven by hand.
#
# LEG 5 -- "netplay: extra explosion?". After a reset, on P1's screen, both ships flew in and then
# P2 EXPLODED instantly again before flying in again. `ManagePuppet` read the peer's `alive` flag
# as a LEVEL: `SpawnAllPlayers` respawns every SEATED slot and the peer's seat is deliberately
# reserved across a death, so ~1.3s into the reset a ship arrived in the Remote seat while the
# peer -- still running its OWN reset -- honestly reported alive=false, and the session played the
# full death FX on a death that never happened. Two halves, both driven here: 5b calls the REAL
# `GameScene.SpawnAllPlayers` (through the `NetSpawnAllPlayersForTest` seam, since its only
# production caller sits behind ~1.3s of choreography this suite does not tick) and requires the
# net-owned seat left alone; 5c puts a Remote ship in that seat by hand -- the pre-card shape --
# and requires it released with NO FX. 5a and 5d are the positive controls: a real death still
# explodes exactly ONCE, before and after. The observable is `metrics.RemoteShipExplosions`,
# which exists because the FX leaves no other headless trace (two Explosions and a cue into a
# live world).
#
# LEG 6 -- "when P1 dies, the whole game rewinds a bit". `Juice.AddHitStop(0.18f)` at
# `PlayerShip.Asplode` halts the dying peer's WHOLE world (Game1.UpdateScaled folds TimeScale
# into the gameTime every component gets) while `NetSession.Update`, outside that scaled path,
# keeps streaming snapshots of the frozen positions -- so the other peer's puppets, which
# dead-reckon on real time by design, run ahead and are then corrected BACKWARD. Measured at 23px
# of backward glide (N=64, 0.15 px/ms) by `python tools/sim/net_puppet_drive_sim.py --hoststall`.
# The fix refuses every hit-stop while a session is active; this leg drives the REAL
# `PlayerShip.Asplode` and reads `Juice.TimeScale`. **LEG 0a IS ITS CONTROL AND IS NOT OPTIONAL** --
# `NetSession.Active` is the gate, so the only moment a "a hit-stop would otherwise land here"
# reading can be taken is before `StartForTest`. Without it leg 6 passes on a build where
# `AddHitStop` is broken outright or `Asplode` stopped calling it.
#
# MUTATION-TESTED THREE MORE WAYS for those legs, each isolated, each failing exactly ONE
# assertion and naming its half:
#   * drop `|| HitStopSuppressed` from Juice.AddHitStop -> **1** (leg 6, "game time was NOT
#     frozen (TimeScale=0)"). Leg 0a still passes, which is the point of taking it offline.
#   * drop the `ControlDevice.Remote` skip from GameScene.SpawnAllPlayers -> **1** (leg 5b,
#     "put NO ship in the peer's Remote seat"). Note it does NOT fail 5b's explosion assertion:
#     the edge fix below catches the ship and releases it quietly, which is the defence in depth
#     working.
#   * revert ManagePuppet's explode to the unconditional level test -> **1** (leg 5c, "it was
#     released with NO death FX (fx+1)"). Reverting BOTH is the true pre-card state and fails
#     both of the above.
#
# DESTRUCTIVE, which is why this probe is a whole process to itself (the runner gives every probe
# one anyway). It pairs a real session onto the live level, moves the local player's seat and
