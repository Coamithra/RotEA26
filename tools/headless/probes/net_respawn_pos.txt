# PROBE: after a death and respawn in online co-op, the other player's ship appears where it
# respawned -- never at the spot it died, sliding fast across the screen to the spawn point.
#
# PINS: card df72b051 ("when the players both die and respawn, the other player appears on the
# wrong position, then gets sync'd (so the ship very quickly moves across the screen to the
# correct position)").
#
# THE BUG. While a peer's ship is dead, SendShipState keeps streaming MsgShipState as the
# heartbeat with alive=false and pos = lastTxPos -- the position the ship DIED at, repeated every
# ~33 ms for the whole death. Every one of those samples landed in the ship interpolation buffer,
# and on the respawn the render clock (~InterpDelayMs = 100 ms behind the newest sample) read the
# dead-period samples FIRST: the puppet materialised at the old death spot and lerped fast across
# the screen to the real spawn point. A both-players-die reset makes the gap seconds long and the
# two points arbitrarily far apart, which is what made it so visible. The buffer's 1 s trim cannot
# save it -- ShipStateBuffer.Add always keeps the last two samples, so the bracketing pair
# straddling the death gap survives whatever the gap length.
#
# THE FIX (receiver-side, no wire change, both roles): NetSession.HandleShipState clears the
# buffer (+ render clock + the pop-metric baseline) on the dead->alive RISING edge, before the
# first alive sample is added, so a new life starts from its own samples and the interpolator can
# never bridge a death. The friend/couch channel never had the bug: a dead extra ship simply
# stops being streamed and any real death gap exceeds the 500 ms FriendTimeoutMs, which destroys
# the whole channel, buffer included.
#
# WHAT IT ASSERTS (Compat/Net/NetRespawnPosTest.cs carries the full reasoning):
#   1. The bridge itself, modelled on a scratch ShipStateBuffer fed through the REAL codec -- the
#      NEGATIVE control: dead-period samples at the death spot plus one alive sample at the spawn
#      point MUST read the death spot at newest - InterpDelayMs, or the rest of the suite asserts
#      against a bridge that does not exist. The cleared buffer beside it reads the spawn point.
#   2. END TO END over a real NetWire: a scripted peer lives at A, dies (60 heartbeat packets
#      still stamped with A -- the poison, asserted as a precondition via StreamRx), respawns at
#      B ~665 px away. The real puppet explodes on the falling edge (RemoteShipExplosions +1),
#      respawns on the rising edge, and over a drive spanning the whole InterpDelay window its
#      position must NEVER come near A (min distance > 200 px) while staying at B (max < 60 px).
#      Then a REORDERED dead heartbeat from the death stretch arrives after the respawn: it must
#      be inert -- both the edge and the alive latch are gated on the sample being IN-ORDER, or
#      the stale packet reads as a fake falling edge (the healthy puppet explodes) and the next
#      alive packet's fake rising edge wipes the fresh buffer.
#   3. THE FRIEND/COUCH CHANNEL (card 14c5943e). It has no alive edge -- a dead extra ship simply
#      stops being streamed -- so its story is the timeout ladder's, and the pre-card ladder was
#      broken in a way that made the card's bridge unreachable ONLY by accident: the "stalled"
#      protection (8s) consults PeerStalled, which arms at 1200ms of TOTAL silence, while every
#      channel's own 500ms boundary fires first -- so the protective arm was structurally dead
#      and a 0.5-1.2s wifi hiccup exploded every couch/AI-friend puppet, against TickFriends' own
#      stated intent. Fixing that (the LINK-QUIET arm: total silence past the channel's own
#      threshold is a hiccup, not a death) would have opened the bridge for a couch ship that
#      died AND respawned inside a protected window, so the RESUME-GAP CLEAR ships beside it: a
#      sample arriving after a gap the channel would normally have died of starts the puppet from
#      its own samples. The legs: a couch DEATH (slot quiet, link alive) still destroys the
#      channel at 500ms and the respawn streams into a fresh puppet at the respawn point; a 700ms
#      link hiccup does NOT kill the puppet; and the stream resuming after the survivable gap
#      reads exactly its own new position, where the gap-bridging lerp would read ~76px short
#      along the line from the pre-gap position.
#
# MUTATION-TESTED FOUR WAYS, failing DISJOINT legs: disabling the rising-edge clear
# (`if (false && ...)`) flips exactly the two distance legs -- "min 0px from A over the drive" /
# "max 665.7px from B", i.e. the puppet is driven straight back to the death spot -- while
# section 1, both preconditions, the explosion leg and the reorder leg stay green; dropping the
# in-order gate (latching remoteAlive raw off every packet) flips exactly the reorder leg, with
# the stale heartbeat exploding the healthy puppet; dropping the link-quiet arm flips the hiccup
# leg (the puppet dies at 500ms of total silence, plus the resume leg it cascades into);
# dropping the resume-gap clear flips exactly the resume leg, at the predicted 76.2px. 23/23
# with the fix.
#
# DESTRUCTIVE, so it gets a process to itself: it pairs a real host session onto the live level
# and seats + explodes a real Remote puppet (real explosions + the expl2 cue). Teardown stops the
# session, removes the puppet ship, frees the Remote seat and asserts the roster is restored.
#
# ?level=Level2 for a level that runs with one keyboard player and a live ship (the suite's rig
# precondition), ?invuln so the settle cannot lose that ship, ?noattract because the suite needs
# the LEVEL and not a demo.
#
# eahl: --flags "?level=Level2&invuln&noattract"

step 400 nodraw
mark
eval NetRespawnPos

expect \[net\] session start role=host .* protocol=v[0-9]+ transport=InMemory
expect \[netrespawnpos\] respawn puppet position
expect 1\. the death-bridge on a scratch buffer
expect 2\. end to end -- a scripted peer dies at A and respawns at B
expect 4\. teardown
# The numbers, not just the leg headings -- the distances are the whole subject. The negative
# control's bridge must really read the death spot, the falling edge must really explode the
# puppet, and the respawned puppet must stay the full screen away from A.
expect NEGATIVE without the clear, the render point \(newest - 100ms\) reads the DEATH position
expect the falling edge exploded the puppet \(RemoteShipExplosions \+1\)
expect PRECONDITION the dead heartbeats kept flowing \(StreamRx \+60\)
expect the respawned puppet NEVER reads near the death spot
expect and stays at the spawn point throughout
expect a REORDERED dead heartbeat is inert: no fake death \(RemoteShipExplosions \+0\), puppet still up
expect 3\. the friend/couch channel -- death, hiccup, and the resume-gap clear
expect a couch death \(slot quiet, link alive\) destroys the channel at its 500ms timeout
expect a 700ms LINK hiccup \(total silence\) does NOT kill the friend puppet
expect the resumed stream starts the puppet from its OWN samples \(0px from C
# A TALLY, never a bare `expect-not FAIL`: an absence assertion passes on a run where the eval
# never happened, and this suite skips its live section on a bad precondition. Raise the count
# when checks are added.
expect \[netrespawnpos\] 23 passed, 0 failed
expect-not FAIL
expect-not SKIP
quit
