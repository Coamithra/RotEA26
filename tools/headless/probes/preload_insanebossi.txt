# PROBE: the Boss Train challenge (InsaneBossI) decodes no textures during gameplay.
#
# PINS: wwwroot/Content/preload/manifest.txt's InsaneBossI section -- at 82 entries the LARGEST
# in the file, because the level runs the whole boss roster back to back. Same silent failure
# mode as preload_level2: that file is pure DATA, so a dropped line produces no build error and
# no failing test, only a stutter the next time somebody plays the level.
#
# FAILURE MEANS: an asset the boss train uses is no longer preloaded, so it is decoded during
# live gameplay = a visible stutter, and on this level that lands mid boss fight. The quoted
# line names it. Fix by restoring the manifest entry (or, if the asset is genuinely new,
# capture it -- see LoadProfiler's header for the eaPreloadExport / MERGE-never-overwrite flow).
#
# THE TRAP, AND WHY THIS DRIVES THE MENU RATHER THAN ?level=InsaneBossI:
# a ?level= boot has no splash, so Game1's QueueIdleWarm assets drain into gameplay and are
# recorded as THAT LEVEL's cold decodes -- exactly 20 spurious gfx/game/space/* lines, measured
# identically on Level2, Paratrooper and InsaneBossI. A probe booted that way either fails
# always or needs a whitelist that would mask the real thing. So: main menu -> Challenges ->
# carousel index 6 -> select -> difficulty -> select.
#
# InsaneBossI is listed as "Boss Train", the SEVENTH challenge (MenuScene.cs: Space Dodge,
# Braineroids, Evil Aliens Classic, Paratrooper, Base Pressure, Crazy Game, Boss Train, ...),
# and the carousel opens on Space Dodge -- hence six rights, as six SEPARATE taps: `eval Press
# right 6` is a six-tick HOLD, not six presses, and moves the carousel once.
#
# THE SOAK MUST OUTLAST THE LEVEL, AND THAT IS THE WHOLE DIFFICULTY HERE. The bosses arrive in
# SEQUENCE, so a window that stops early never reaches the later ones and silently defends only
# the front of the manifest. Measured hole at the 180s length this probe was first written with:
# deleting the WHOLE InsaneBossI section surfaced 23 cold assets at 180s but 25 at 720s, and
# deleting just the two it never got to -- InsaneBossI|gfx/base/756 and |gfx/base/2331-v5 --
# left the probe PASSING. So the soak runs the level OUT: ~420 simulated seconds of play plus
# slack, i.e. 43200 frames. That costs ~3.5s wall, not 12x the 180s run, because once the level
# ends the remaining frames tick a menu (TIMEOUT_S in run_probes.py is 300).
# As on preload_paratrooper, the post-level tail is wanted rather than tolerated:
# LoadProfiler._currentLevel persists past a level by design, so the tail extends the assertion
# over the results/menu path, and a window trimmed to the finishing frame would be fragile
# because that frame moves with the AI. Measured clean over five runs at this length.
#
# THE TWO ASSERTIONS BELOW THE SOAK ARE BOTH ANTI-VACUITY GUARDS, and neither is decoration:
#   - the `expect ... preload:` pins WHICH level loaded, so a carousel reorder that landed the
#     run on a different challenge cannot sail through (the `expect-not` only ever mentions
#     InsaneBossI, so it would find nothing and pass).
#   - the `expect ... s0=` pins that the level was PLAYED rather than merely entered. Without
#     it, a change that wedged or instantly killed the bot at spawn would still preload, still
#     match the line above, and still go green over a window containing no gameplay. The
#     ScoreDump is sampled MID-level (the score component is gone once the run is back on the
#     menu, so a sample after the soak prints nothing at all). The floor is four digits, i.e.
#     >= 1000, against a measured 22334/35857/51942 at that mark over three runs -- a progress
#     check, not a performance one; widen the margin rather than tightening it.
#
# ?unlockall so the challenge is selectable from a wiped save; ?invuln + ?aiplayer so the level
# is actually played rather than sitting on a dead ship. (This level runs with score.Lives = -1,
# so a stuck bot shows up as the level not progressing, never as a GAME OVER -- which is exactly
# what the score assertion is there to catch.)
#
# eahl: --flags "?menu&noattract&loadlog&unlockall&invuln&aiplayer"

eval Press down 1

eval Press down 1

# population and a different card's business -- drop them so this window is InsaneBossI's
# alone. Nothing here depends on how MANY of them there are.

expect-not COLD decode in InsaneBossI
