# PROBE: a default eahl run is silent, and provably so at the mixer.
#
# PINS: HeadlessAudio. A background soak must never play the game's SFX through the
# user's speakers -- an agent cannot hear it, so nothing else would notice. It was
# broken for the whole of eahl's first life precisely because nothing was watching.
#
# FAILURE MEANS: the run is (or may be) audible. Read the quoted `ok audio` line:
#   masterVolume=1      -> the mute was not applied at all
#   alGain=1            -> HeadlessAudio.Pump never landed, or something re-asserted the
#                          listener gain mid-run
#   alGain=<unreadable> -> NOT a pass: silence was not confirmed, so it is reported as a
#                          failure rather than skipped. The same line says which of the three
#                          causes it was (card 72297923): device=none is a box with no audio
#                          device, lib=<unresolved> is the OpenAL binary not resolving, and
#                          device=ok with a readable lib is OpenAL simply not up yet.
#                          A genuinely device-less box FAILS this probe, deliberately -- the
#                          suite's contract is "this box can confirm mixer silence", and one
#                          that cannot should be loud rather than green. It is no_audio_device.txt
#                          that covers such a box, and the fix for a new PLATFORM is to add its
#                          library name to HeadlessAudio, never to relax the assertion.
#
# WHY IT FIRES A SHOT: KNI brings OpenAL up lazily on the FIRST sound, and until then the
# gain cannot be read back at all. Menu navigation produces no sound, so the probe has to
# make one -- and it makes it DELIBERATELY, with the player's own gun, rather than idling
# in a level and hoping the auto-pilot shoots. 400 frames is the level intro settling; the
# ship does not exist to fire before that. Reliable 5/5.
#
# The negative control is not scripted, it is a flag: the same probe under --audio must
# FAIL with masterVolume=1 alGain=1. Re-run it that way if you ever doubt this file.
#
# eahl: --flags "?level=Level1&invuln"

step 400 nodraw
eval Press fire 60
step 200 nodraw
mark
audio

# Asserted per field rather than against the whole AudioStatus() line, so adding a field to
# it does not turn every future run red for the wrong reason.
expect ^ok audio .*\bmasterVolume=0\b

# Added by card 72297923, which made the readback resolve OpenAL through KNI's own candidate
# list instead of naming soft_oal.dll outright. It asserts the P/Invokes bound to SOMETHING
# without saying to what, so it reads the same off Windows -- where a wrong candidate list is
# exactly what would break.
#
# It is ORDERED BEFORE the alGain assertion on purpose, and that ordering is the whole of its
# value: a failed resolve also makes alGain unreadable, so this discriminates no mutant that
# the next line would miss. What it does is make the run say WHICH fault it hit -- "the OpenAL
# binary did not resolve" instead of the far vaguer "the gain is not zero". Do not reorder it
# below the next line; that is where it was first written, and it never got to fire.
#
# No trailing \b: '>' and the following space are BOTH non-word characters, so there is no word
# boundary between them and the assertion passed on a line that plainly said lib=<unresolved>.
# Caught by the mutation test, which is the only thing that would have caught it.
expect-not ^ok audio .*\blib=<unresolved>

expect ^ok audio .*\balGain=0\b
quit
