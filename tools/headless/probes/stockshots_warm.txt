# PROBE: every level-select carousel entry's stock art is preloaded, none decodes cold.
#
# PINS: ScreenshotSaver.StockShots, which since card 8d6883f3 is DERIVED -- every level whose
# LevelArt.ScreenshotPath is non-null contributes it, deduped. Both consumers
# (ScreenshotSaver.Init and Game1.QueueMenuWarm) iterate that one list, and SubMenuLevelChoice
# resolves each carousel entry's image through the same ScreenshotPath lookup.
#
# FAILURE MEANS: a carousel entry's art is no longer in the preloaded set, so it decodes
# (900x700, ~30-40ms in Chrome) the first time the player opens that carousel. That is EXACTLY
# the bug card 4d47c5ba fixed: ScreenshotSaver.Init hardcoded eleven of the twelve and the one
# it missed -- gfx/screenshots/webcamss, the challenge carousel's LAST entry -- decoded cold on
# first opening Challenges, unnoticed for however long it had been true. Fix by restoring the
# level to LevelArt.ScreenshotPath, NOT by re-hardcoding a list.
#
# THE COLD ASSERTION CAN NO LONGER CATCH A DROPPED LEVEL ON ITS OWN (card 0d166364). Read this
# before deleting anything here as redundant. The probe originally rested entirely on the COLD
# line, because a level dropped from the old LevelArt.HasCarouselEntry lost its warm slot while
# SubMenuLevelChoice still resolved its REAL path -- so the carousel went and fetched it and the
# decode was visible. 0d166364 collapsed HasCarouselEntry into ScreenshotPath returning null,
# and that kills the signal: a dropped level now resolves to null in the carousel too and falls
# back to GFX/Screenshots/level1empty, which is ALREADY WARM. Nothing decodes. Measured: with
# only the COLD line, the WebcamAliens mutation passes green.
#
# So a drop is caught by the other two, and they catch DIFFERENT things -- neither is redundant:
#   * `stockshots warm: 12 textures` (the boot leg, card 2367b39c) counts the derived set, so it
#     fires first and hardest on a level deleted from ScreenshotPath: it reads 11.
#   * `[levelart] carousel entry` is the ONLY one that catches the drift this card is actually
#     about -- a carousel entry authored in MenuScene for a level with NO ScreenshotPath row.
#     StockShots is still twelve in that state and the boot count passes happily; the warning
#     SubMenuLevelChoice.loadScreenshots prints on its fallback is the sole evidence, and it
#     names the LEVEL rather than an asset path. Measured, not assumed: authoring a
#     `levelSelector` entry for Levels.Tutorial leaves the boot count and COLD both GREEN and
#     turns this line alone red, naming Tutorial.
# COLD stays because it still covers regressions on the ScreenshotSaver/QueueMenuWarm side that
# neither of the others can see.
#
# WHY IT OPENS BOTH CAROUSELS: `SubMenuLevelChoice.loadScreenshots` loads EVERY entry's image
# in one loop, so merely opening a carousel demands all of its art -- no walking required. But
# there are TWO of them, `levelSelector` (the three missions) and `challengeSelector` (the nine
# challenges), each with its own Initialize. Opening only Challenges leaves level1/2/3empty
# undemanded, and a probe that did that PASSED with Levels.Level1 deleted from
# the membership list (measured). So: Start Game to open the mission carousel, back out, then
# Challenges.
#
# THE POSITIVE CONTROL is the launch at the end. `expect-not COLD ... gfx/screenshots/` passes
# beautifully on a run that never opened a carousel at all -- and it very nearly shipped that
# way here, because ?autostart silently swallows menu keypresses and the whole run sat on the
# main menu looking green. `[loadprofile] TeamChallenge preload:` can only be reached by
# navigating into the CHALLENGE carousel and walking seven entries along it, so it proves the
# window this probe asserts over is the real one. Boot with ?menu (what the other menu-driven
# probe uses), never ?autostart. The mission leg has no equivalent control of its own: it is
# covered transitively, since the same keypress stream has to have worked to reach the launch.
#
# WHERE THE `mark` GOES, and this is the whole probe: a SubMenuLevelChoice loads its entry art
# in its own Initialize, which KNI runs when the submenu is first ADDED -- i.e. the moment the
# player opens that carousel, not when the MenuScene is built. So a dropped level's art decodes
# in the beat between pressing select and the carousel appearing. Mark AFTER the settle but
# BEFORE navigating: a mark placed after the carousel is up sits one step too late, the
# offending decode lands in the dropped window, and the probe passes on the very mutation it
# exists to catch (measured -- it did).
#
# THE THREE ASSERTIONS BEFORE THE MARK are the boot leg (cards 2367b39c, cccd763a). Under ?menu
# the splash is skipped and Start is auto-pressed on frame 1, so the pump gets through only the
# first couple of entries -- and the menu's own twelve are queued AHEAD of the stock shots -- so
# all twelve decode inside ScreenshotSaver.Init during boot. That is the debug path, not a
# regression -- and since 2367b39c Init brackets the loop as a labelled warm, so it reports as ONE
# `stockshots warm:` summary instead of twelve COLD lines.
# Asserting on that summary pins the attribution AND counts the set: a level dropped from the
# carousel reads `11 textures` here, caught at BOOT, before the navigation below has run at all.
# They sit before the mark because the mark is what throws that window away.
#
# The `menu warm drain:` line is the third, and this is the only probe positioned to hold it: it
# prints from Game1.DrainWarmQueue only on a boot that reaches the handoff with the queue still
# non-empty, which is exactly what ?menu produces and what a full-splash probe never can. Nothing
# else asserts that diagnostic exists, and its failure mode is silent -- you find out the next
# time you need the number (card cccd763a). The COUNT is deliberately not pinned: it is however
# many entries the pump had not reached, i.e. a tick-timing detail, not a contract.
#
# **ADDING a carousel level bumps the literal to 13 -- update it here.** Card 8d6883f3 made the
# set derive from LevelArt so an addition costs no code, and this pin is the one place that still
# has to be told. A stale literal fails as though the addition were a regression; it is not.
#
# The `expect-not` under it is NOT the main anti-COLD assertion -- the summary line above already
# fails if the bracket is gone. It covers the narrower case the summary cannot see: a
# gfx/screenshots/* decode at boot from OUTSIDE Init's bracketed loop (a thirteenth load added
# elsewhere), which is the card's literal acceptance criterion.
#
# ?unlockall so a wiped save can select the later challenges; ?invuln so the launched level
# does not die during the settle.
#
# eahl: --flags "?menu&noattract&loadlog&unlockall&invuln"

step 150 nodraw

# The boot leg: ScreenshotSaver.Init decodes the whole stock set here (under ?menu the pump never
# reaches them), and since card 2367b39c it is bracketed, so it must report as one labelled
# summary naming all twelve -- never as COLD gaps. The count is what catches a dropped carousel
# level at boot. The drain line is the handoff's own cost, printed right after. All three must
# precede the mark, which discards this window.
expect \[loadprofile\] stockshots warm: 12 textures
expect-not COLD decode in \(boot\): gfx/screenshots/
expect \[loadprofile\] menu warm drain:

# Now drop the boot window, so the only decodes left are ones the carousel had to go and FETCH.
# The mark must sit BEFORE the navigation below -- see the header.
mark

# Start Game -> the MISSION carousel (its Initialize decodes level1/2/3empty), then back out.
eval Press enter 1
step 90 nodraw
eval Press esc 1
step 90 nodraw

# Main menu -> Challenges (three down from Start), then into the carousel. Its Initialize
# decodes all nine challenge thumbnails.
eval Press down 1
step 90 nodraw
eval Press down 1
step 90 nodraw
eval Press down 1
step 90 nodraw
eval Press enter 1
step 90 nodraw

# Walk to Team Challenge (index 7 of 9) and launch it -- the positive control. The walk buys no
# extra COLD coverage (the carousel already loaded every entry above); it is only how the run
# reaches a launchable entry, and how the control proves the navigation worked.
eval Press right 1
step 30 nodraw
eval Press right 1
step 30 nodraw
eval Press right 1
step 30 nodraw
eval Press right 1
step 30 nodraw
eval Press right 1
step 30 nodraw
eval Press right 1
step 30 nodraw
eval Press right 1
step 60 nodraw

# Difficulty screen, then select.
eval Press enter 1
step 120 nodraw
eval Press enter 1
step 240 nodraw

expect \[loadprofile\] TeamChallenge preload:
expect-not COLD decode in .*: gfx/screenshots/
# The live signal since card 0d166364 -- see the header. Names the LEVEL, not the asset:
# `[levelart] carousel entry WebcamAliens has no bundled art`.
expect-not \[levelart\] carousel entry
quit
