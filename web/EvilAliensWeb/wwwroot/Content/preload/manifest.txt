# Evil Aliens preload manifest — read at level-load time by Compat/LoadProfiler.cs.
#
# Each line preloads one texture for one level, ON TOP OF that level's
# PreloadGraphicalContent() code list. It exists so newly-added art that isn't in
# the code list can be warmed without editing C#, and so the debug profiler can
# grow this file automatically (see below).
#
# Format:  <Level>|<asset-path>[|COLD|<ms>|<WxH>]      (# = comment, blanks ignored)
#   <Level>      a Levels enum name (Level1, Level2, TeamChallenge, ...)
#   <asset-path> Content-relative, lowercase, no extension (e.g. gfx/sprites/eye_idle)
#   trailing fields (optional) are profiler bookkeeping: COLD/WARM, worst decode ms,
#                  pixel size. The loader ignores them; only <Level>|<asset-path> matter.
#
# HOW TO GROW THIS FILE: run the game with ?loadlog, play the levels you care about
# (cold decodes are logged to the console as they happen and saved to localStorage),
# then run  eaPreloadExport()  in the browser console — or, preferably, do the whole
# thing headlessly with  eahl --repl  and  eval PreloadExport.
#
# MERGE the per-level sections it gives you into the CAPTURED SECTIONS block at the
# bottom of this file. Do NOT replace this file with the export: the export contains
# only what that one session recorded, so overwriting deletes every level you did not
# play. See that block's header for the two ways a capture comes back short, and read
# the capture gotchas in web/EvilAliensWeb/CLAUDE.md before taking one.
#
# Release builds only READ this file; they never record or append.

# CAPTURED SECTIONS -- tool output, do not hand-edit.
#
# Everything ABOVE is hand-written per theme. Everything BELOW is the verbatim
# per-level output of  eval PreloadExport  (browser: eaPreloadExport()). A level
# that appears here must NOT also appear above -- WarmThenLaunch enqueues every
# manifest line, so a duplicate is warmed twice.
#
# RE-CAPTURING: take the new section as a UNION with what is already here, never
# a blind overwrite. Two ways a capture silently comes back SHORT:
#   * The content manager is shared and never unloads, so any asset an EARLIER
#     level in the same process already decoded is missing from a later level's
#     section. (Demo2 below was captured from the attract rotation, which runs
#     Demo1 first -- its brainanimated lines are absent from that export and are
#     preserved here from the previous file.)
#   * A run that ends early never reaches a level's later phases. Some entries
#     are also DEFENSIVE rather than observed -- asteroidsmall1..4 are listed
#     because the spawner picks one of the four at random, not because any one
#     run saw all four -- and those only survive a re-capture because warming
#     them makes them show up again.
# So: union, and check the section did not shrink.
#
# HOW THESE WERE TAKEN (card 74b30beb): eahl --repl with
# ?menu&noattract&unlockall&loadlog&aiplayer&invuln, driven through the MENU with
# `eval Press`, then `eval PreloadExport`. The menu path matters -- a ?level= boot
# has no splash, so Game1.QueueIdleWarm's 21 space/star assets drain into live
# gameplay and get mis-recorded as that level's assets. Demo2 is not menu-
# selectable, so it was taken from the idle attract rotation instead.
#
# THE GAP THESE FIX: Background.SetMars() loads the 12 marsloop ground tiles (plus
# marshills1-3 and the two cloud layers) SYNCHRONOUSLY in the level's Initialize()
# -- which runs AFTER Game1.WarmThenLaunch's pre-launch warm bracket and BEFORE
# GameScene.LoadContent's own bracket. So nothing warmed them and each level paid
# ~1.2s of decode on its first gameplay tick (browser-measured ~110ms x 12), which
# the hitch watchdog reported as repeated [hitch] 12x-134ms frames. Listing them
# here moves the decode into the pre-launch warm, which is pumped before the scene
# is constructed, so SetMars's Content.Load calls are cache hits.
#
# The WARM lines are deliberate: they are already loaded by the scene's own
# PreloadGraphicalContent, and naming them here moves that whole synchronous
# bracket onto the pumped pre-launch ticks instead of one blocking load tick --
# which is what the pre-launch warm exists for. (PumpLevelWarm is budgeted per
# tick, so a section this long does not add a per-entry frame of latency.)
#
# GOTCHA when capturing a level with NO lines here yet: WarmThenLaunch bails out
# early when a level has zero manifest assets, so no preload bracket is opened and
# the level's Initialize decodes are attributed to the "(boot)" sentinel instead of
# the level. That takes two passes -- seed the section from the (boot) block
# immediately preceding the "<Level> preload:" summary line, then re-capture.
# (Paratrooper below was seeded that way.)
# ===========================================================================
